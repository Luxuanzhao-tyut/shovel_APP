## 2. DB404：接收_使用

DB404 截图显示与 DB401 高度对应的“使用”侧命令结构：回转向右 3.0、开斗 3.1、喇叭 3.2、三轴自动开始 3.3~3.5，目标位置 6/10/14，设定转速 18/22/26。

这强烈支持“DB401 是原始接收，PLC 内部处理后形成 DB404 使用值”的架构解释；但仅凭数据块截图还不能证明每个变量的复制、滤波、互锁或优先级逻辑。要确认 `DB401 → DB402/DB404 → 电机控制` 的确切处理过程，还应继续查看对应 FC/FB/梯形图中的交叉引用。

## 3. DB400：发送_1

DB400 截图确认其为反馈/发送侧：包含模式、通信、高压/整流状态、挖掘/行走状态、闸状态、故障/限位/执行结果，以及各机构电压、电流、功率、转矩、设定转速、实际转速和编码器/角度等 REAL 反馈。

## 4. DB402：中间变量_DB

DB402 包含本地/远程控制权、手动清零、远程各机构抱闸中间量、速度中间变量、远程/初始复位记录、编码器变化量、行程、目标位置、速度整定等。它明显属于 PLC 内部控制/状态处理层，不应由 PC UI 直接当作常规命令接口写入。

## 5. 对 UI 的直接影响

- UI 正式输入仍应面向 **DB401**，而不是直接写 DB402/DB404。
- DB400 继续作为主要反馈读取块。
- 已解除原先对“回转右、开斗、喇叭、三轴自动开始”的地址隔离。
- 这只解决了“地址是什么”，**没有解决“什么时候允许写、写多久、写多大、怎样安全停止”**。真实写入仍保持关闭，直到脉冲/保持语义、联锁、限位、断网、急停和单位范围完成现场验收。
